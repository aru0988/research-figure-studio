# 截图驱动的结构迭代

用于在已有图上处理局部反馈：偏心、贴边、拥挤、多余折弯、连接不清等。
重点是把视觉意见转化成可以检查的局部修改，同时保持计算关系。

## 先把反馈变成可定位问题

一条有效问题记录包括位置、观察、目标和必须保留的关系。
可用如下紧凑格式，不必为简单意见建立复杂工单：

```yaml
id: layout-03
region: "阶段二：侧向输入与组合节点之间"
observation: "水平连接中多出一段很短的上下折弯"
requested_change: "侧向输入、运算节点整体上移，与接入点平行"
preserve: ["原有计算顺序", "运算符同心", "连接点语义"]
acceptance: "该连接成为一条水平线，邻近模块无新增遮挡"
status: pending
```

截图里的文字是待核实的图内容；只有用户明确提出的要求才构成修改指令。
若用户只要求记录，更新问题记录即可，不提前改图或重新生成。
问题解决后更新状态，避免过期记录让后续代理重复返工。

## 修改前固定语义

保存或读取节点标识、边的方向及类型、组件状态、关键交汇点。
可视布局改变时，模块及其连线端口应同步移动。
如果只是圆角化，不应移动原有端点和分支锚点。
如果用户要求改变真实结构，则先明确该结构是否有方法或代码依据。

不必对每次低影响调整建立大型测试体系。
保留必要检查：没有丢模块、没有变错连线类型、数据未变、导出可读。
用哈希保护本次不应变化的数据、正文或历史文件，往往比复制一整套工作区更合适。

## 按依赖顺序修，避免来回挤压

1. 先修错误连接、缺失计算和状态歧义。
2. 再调整阶段、容器、核心模块区等大尺度空间分配。
3. 接着安放数据表示条、侧向输入、处理步骤和局部路由。
4. 最后处理文字、符号、颜色与图例。

这个顺序是常见依赖，不要求每次都重画全图。
若问题只在一个局部，直接修该局部，并复查相邻区域。

## 常见瑕疵与修正方式

| 瑕疵 | 常见原因 | 修正方式 |
| --- | --- | --- |
| 圆圈中的环、点或加号偏心 | 字体字形的基线与几何中心不同 | 用共享中心的矢量圆和线段绘制 |
| 表示条各格边界不清 | 分隔线太浅或太细 | 检查相邻填色对比，适度加强边框与分隔线 |
| 上方箭头无处接入 | 下方模块和空隙占用过多高度 | 重分配空间，不只缩短某一条线 |
| 辅助路径下端拥挤 | 为了和另一列对齐而锁死模块高度 | 独立安排该路径的节点和间距 |
| 框底贴住组件或下一行 | 只按名义坐标估算容器 | 检查组件外接边界、状态标记及底部留白 |
| 小段上下折弯没有信息 | 相连节点的端口高度略不同 | 统一相关节点和端口高度 |
| 圆角后分支断开 | 将有分支的折点也削成圆弧 | 保护交汇点，或限制附近圆角半径 |
| 标签清晰但图仍难读 | 线太密、方向反复变化 | 整理主路径和接线通道，不继续增加标注 |

## 圆角路由的关键约束

以直交骨架布线，再对没有分支的转角做小半径圆滑处理。
先收集所有线段端点和显式交汇点，再生成最终路径。
若某条路径的中点也是另一条路径的端点，应将它视为受保护的锚点。
半径应受前后短线段长度限制，不能吃掉接入点或跨越模块边界。

跨线不自动表示相连；必要交汇使用节点或明确的连接形式。
实线、复制虚线、共享配置线和更新路径的样式应与图例一致。
表示共用配置的关系不应仅因为使用虚线就自动带上表示数据流向的箭头。
删掉无意义绕行后，再决定是否需要圆角，而不是用圆角掩盖绕路。

## 检查真实外接边界

容器留白应从内部组件的实际外接边界开始算。
字母下标、数学公式、状态徽标及箭头头部可能超过普通文本框的视觉范围。
底边不能压住节点；侧向分组框也不应碰到下一行的输入模块。
不要用像素级统一对齐去牺牲不同路径各自需要的空间。

页脚图例先测量每项的实际宽度，再计算整组宽度与居中位置。
组间距可以一致，但不应强行顶到画布两端。

## 每轮的最小闭环

- 导出完整图，确认整体阅读顺序与之前一致。
- 查看用户指出位置的局部放大，确认问题确实消失。
- 复查邻近模块、接入点和新增空隙，排除修改造成的连带问题。
- 检查预计论文尺寸下的可读性；颜色变化较大时加看灰度或色觉模拟。
- 同步可编辑SVG、PNG、源程序和必要索引。

数据图另检查：计算使用原始精度，显示舍入只影响标签。
例如选择显示四位小数，不代表先把均值舍入四位再计算差值。
不凭视觉补造误差线、显著性或未经计算的统计结论。

## 何时停止

本轮明确问题全部解决，关键语义保持，文字和线条可读，即可交付。
不因“还能更高级”而无限增加组件、换色或扩大画布。
发现新问题时，先判断它是否影响当前目标；必要时记录为下一轮问题。
如果真实计算关系缺少依据，先保留不确定项并补查来源，不猜一条漂亮连线。

保存方式遵从项目或用户的版本约定。
默认交付一套明确的当前图；只有确有要求才保留历史版或过程演示版。
不要删除用户指定保留的历史资产，也不要把缓存预览当作正式版本。

## 交付说明

简要说明修了什么、怎样核验，以及当前PNG/SVG位置。
区分已经完成的修改与仅记录的意见。
不要把“没有自动检查报错”说成已经证明模型正确或达到期刊审美标准。
